## 2024-05-23 - [Secure Auth Storage]
**Vulnerability:** The `auth` slice of the Redux state was being persisted using `AsyncStorage` via Redux Persist. This slice contains the `session` object, which includes the `access_token` and `refresh_token`. `AsyncStorage` is unencrypted on Android and often insecure on iOS, exposing user tokens to potential extraction if the device is compromised or backup data is accessed.
**Learning:** Redundant persistence layers can introduce security vulnerabilities. Supabase's client library already handles session persistence securely (prioritizing `SecureStore`), so persisting the same data via Redux (using `AsyncStorage`) created an unnecessary attack surface.
**Prevention:** Always verify if a third-party SDK (like Supabase or Firebase) already handles secure storage of credentials before implementing your own persistence logic. Explicitly blacklist or exclude authentication state from general-purpose unencrypted storage solutions.
